Cloud Burrito

A read-only macOS desktop app for browsing AWS across many accounts — without clicking through the console. One window, a grid of small panels. It shows things; it never creates, updates, or deletes.

  • macOS
  • Tauri 2 · pure Rust
  • aws-sdk-rust
  • registered read operations only
  • one .app / .dmg
  • no second process

01 Overview

What this is and why it exists.

The AWS console is organised by service: CloudFormation here, CodePipeline there, CloudWatch somewhere else. But real work is organised by task — "is that pipeline green?", "why did this stack fail?", "where do these log errors come from?". Answering one question means opening several services in several tabs, often across several accounts.

Cloud Burrito gives you one window of task-shaped widgets instead. Pick an account at the top and the widgets fill in. Each widget answers one question and lays out its answer as a small table, chart, or log. No tab-hopping, no console navigation.

It is read-only by construction. The app can only look — it has no ability to change anything in your AWS accounts. That is a property of how it is built, not a setting you can flip. See Architecture for exactly how that works.

In one sentence

Pick an account, get a dashboard of small read-only panels that answer the questions you actually have — across every account you already have AWS access to.

02 Architecture

One program, three layers, no second process.

Cloud Burrito is a single Rust / Tauri 2 program. It is pure Rust and talks to AWS directly through the AWS SDK for Rust. Earlier versions ran a separate Python sidecar process to reach AWS — that is gone. There is no Python anywhere, and no second process to manage.

The three layers

  • (a) The window — an HTML / CSS / JS frontend. This is just the UI: it draws the grid, the tiles, and the tables.
  • (b) The Rust app — Tauri command handlers. It resolves your SSO login, runs the dashboard and drill-down widgets, and writes the audit log. Crucially, every AWS service call is policy-gated and read-only.
  • (c) AWS — reached via aws-sdk-rust using your profile's credentials. Nothing sits between the Rust app and AWS.

The window talks to the Rust app by calling commands with Tauri's invoke(). The Rust app talks to AWS with the SDK. That's the whole picture.

Authorization & login

The app reuses the AWS CLI's SSO login. It never stores a password, access key, or token of its own. Here is exactly what happens:

  1. Profiles come from ~/.aws/config — the same file the AWS CLI uses.
  2. You pick a profile. The app resolves credentials the same way the CLI does: it reads the cached SSO token from ~/.aws/sso/cache.
  3. It exchanges that token for short-lived role credentials and auto-refreshes them as they expire.
  4. Those credentials live in memory only, for this session only. Nothing is written to disk.

If the cached SSO token has expired, the app tells you to run aws sso login — it cannot log you in itself. It uses whatever role the profile grants; it does not assume any special or elevated role.

Why read-only — two reasons

  • Structural. Only read operations are built into the binary. There are no write calls to make. The app physically cannot write, even if you point it at credentials with full admin rights.
  • Auditable. Every AWS call is logged to ~/.cloud_burrito/audit.log, and a live Audit panel inside the app shows the same feed in real time. You can always see exactly what it did.
  • User-narrowable. On top of the structural floor, a user-editable ~/.cloud_burrito/policy.yaml (an IAM-style allowlist, editable from the Settings panel) can further restrict which read operations the app may call — it can only narrow the allowed set, never re-enable writes.

Where data lives

  • ~/.aws/config Profiles by the AWS CLI
  • ~/.aws/sso/cache Cached SSO token by the AWS CLI
  • ~/.cloud_burrito/settings.json App settings by the app
  • ~/.cloud_burrito/dashboard.json Tile layout by the app
  • ~/.cloud_burrito/audit.log Every AWS call by the app
  • ~/.cloud_burrito/policy.yaml IAM-style read-op allowlist (editable in Settings) by the user

03 Using the app

Pick an account, arrange your widgets, watch the audit feed.

Pick account & region

At the top of the window, choose an account (a dropdown built from the profiles in ~/.aws/config) and a region (for example eu-west-1 or us-east-1). Every widget reads from that account and region until you change it.

The auth pill

Next to the selectors, an auth pill shows your login status. When you're signed in it reads auth: ok · <account> · 9h left; when the SSO token has lapsed it turns amber: expired — run aws sso login. Click the pill to open the Identity panel and see exactly who you are signed in as.

Working with widgets

Some widgets need an input — a pipeline name, a log group, a search term. Type it into the tile. Refresh any tile with its ↻ button.

Each tile has a gear (⚙) for per-tile settings. From there you can:

  • Override account / region for that one tile — handy for watching prod and staging side by side.
  • Set a header colour to group or flag tiles visually.
  • View the widget's source to see exactly which AWS calls it makes.

You can drag and resize tiles freely. The layout auto-saves and restores — close the app and your dashboard comes back exactly as you left it (stored in ~/.cloud_burrito/dashboard.json).

Settings & audit

Settings shows your config path, the active SSO session, and your defaults. The Audit panel is a live feed of every AWS call the app makes — the same content that streams to audit.log.

04 Widgets

Six task-shaped panels. Each answers one question.

WidgetWhat it showsService
CloudFormation Stacks Your stacks with their status and resource count. CloudFormation
Pipeline Runs Recent executions of one CodePipeline, colour-coded by result. CodePipeline
Log Tail Recent events from a CloudWatch Logs group, with an optional filter. CloudWatch Logs
Errors by Stack Count of ERROR lines per log group over a time window. CloudWatch Logs Insights
Resource Reverse Lookup Find resources by an ARN substring, and the stack that owns them. Tagging API + CloudFormation

Widgets ship inside the binary. To see exactly what one does, open its gear (⚙) and choose view source.

05 Run & build

What you need, how to run it in dev, how to ship a build.

Prerequisites

  • Rust and the Tauri CLI.
  • AWS SSO already configured (you can run aws sso login and use the CLI).
  • No Python — the old sidecar is gone.

Develop

./scripts/dev.sh   # = cargo tauri dev

Build a release

cd src-tauri
cargo tauri build

This produces a .app and a .dmg under src-tauri/target/release/bundle/ — one self-contained app, with no Python runtime bundled in.

Sharing the app

Cloud Burrito deliberately does not use a publisher identity. macOS may reject downloaded unsigned applications, so share the tagged source and let each user build locally.

06 Project layout

Where things live in the repo.

  • frontend/ The UI window
  • frontend/vendor/ gridstack, kept locally so it works offline window
  • src-tauri/src/commands.rs Tauri command handlers backend
  • src-tauri/src/aws/ Credentials, ~/.aws/config parsing, read-only guard backend
  • src-tauri/src/widgets/ Dashboard and drill-down widgets backend
  • src-tauri/src/audit.rs Audit log backend
  • src-tauri/src/settings.rs Settings backend
  • src-tauri/src/dashboard.rs Tile layout backend
  • src-tauri/src/state.rs Shared state backend
  • info/ This documentation page docs
Why this split matters

The window calls the command handlers by name. That clean boundary means the Rust backend can be rewritten without touching the UI — and the UI can be reworked without touching the backend. (That is exactly how the Python sidecar was swapped out for pure Rust with no change to the window.)

07 Troubleshooting

Common snags and the fix for each.

SymptomFix
expired

Your SSO token has lapsed. Log in again, then re-pick the account in the app:

aws sso login --sso-session <name>   # or: --profile <name>
Empty account dropdown

The app found no usable profiles. Check that ~/.aws/config contains [profile …] entries with an sso_account_id.
A widget says AccessDenied

The profile's role does not have permission for that read. Pick another profile whose role does. The app only ever asks for read access — it cannot escalate.
The window won't open in dev

Run the dev command directly from src-tauri/ and read the terminal output — the error is almost always printed there.

cd src-tauri
cargo tauri dev
